### Перебор делителей до корня
Вот ответ на вопрос: почему ограничение делителей квадратным корнем корректно?
1. Парность множителей: Если составное число N делится на какое-то число a, то результатом деления будет другое число b, которое тоже является делителем N (N / a = b). То есть у каждого делителя a есть «парный» делитель b.
2. Граница корня: Невозможно, чтобы оба парных делителя (a и b) были больше квадратного корня ($\sqrt{N}$), так как их произведение тогда будет строго больше самого числа N ($\sqrt{N}  \times \sqrt{N} = N$).
3. Вывод: Следовательно, по крайней мере один из множителей (меньший или равный из пары) обязательно должен быть меньше либо равен \($\sqrt{N}$)

### Псевдокод сортировки выбором

```
SelectionSort(A)
    n = length(A)
    for i = 0 to n - 2 do
        min_idx = i
        for j = i + 1 to n - 1 do
            if A[j] < A[min_idx] then
                min_idx = j
            end if
        end for
        if min_idx != i then
            swap A[i] and A[min_idx]
        end if
    end for
```

### Псевдокод бинарного поиска
```
BinarySearch(A, n, T)
    // A - отсортированный массив, n - размер массива, T - искомое значение
    low = 0
    high = n - 1

    while low <= high do
        mid = low + floor((high - low) / 2)
        
        if A[mid] == T then
            return mid
        else if A[mid] < T then
            low = mid + 1
        else
            high = mid - 1
            
    return -1 // Значение не найдено
```

## Задание 3. Коллекции и выбор структуры данных
### Ответы на вопросы про структуры данных
1. Почему множество подходит для хранения уникальных значений?

Ответ: множество по определению хранит только уникальные элементы: добавление уже существующего ничего не меняет. Плюс проверка x in students — O(1) в среднем. Со списком пришлось бы вручную отсеивать дубликаты и делать in за O(n).

2. Почему кортеж можно использовать как ключ словаря?

Ответ: Ключом словаря может быть только хэшируемый (hashable) объект, а хэшируемы только неизменяемые объекты. Кортеж неизменяем, и если все его элементы хэшируемы (строки 'anna', 'lab_01' - да), то и ("anna", "lab_01") - годный ключ. Именно поэтому best_score[("anna", "lab_01")] работает.

3. Почему список нельзя использовать как ключ словаря?

Ответ: list - изменяемый. Его хэш пришлось бы пересчитывать при каждом изменении, что сломало бы инварианты хэш-таблицы. Python просто запрещает: TypeError: unhashable type: 'list'. Если бы мы попытались best[["anna", "lab_01"]] = 5 - получили бы эту ошибку.

4. Почему словарь предпочтительнее списка для частого поиска результата по составному ключу?

Ответ: Список - линейная структура: чтобы найти результат для ("anna", "lab_01"), пришлось бы перебрать все попытки (O(n)), сравнивая по полям. Словарь даёт доступ по ключу за O(1) в среднем. Когда ключ составной (кортеж из нескольких полей), словарь превращает «двойной цикл поиска» в один `dict[key]`.

### Временная средняя сложность для использованных коллекций

| Словарь | O(1) | O(1) |

## Задание 4. Функции, параметры и области видимости

Дан код:
```py
course = "Python"

def foo():
    course = "Programming"

    def bar():
        nonlocal course
        course = "Fundamental of Programming"
        print(course)

    bar()
    print(course)

foo()
print(course)
```

В Python для неквалифицированных имён действует порядок LEGB:

1. Local — локальная область текущей функции.
2. Enclosing — объемлющая функция, если текущая функция вложена.
3. Global — глобальная область модуля.
4. Builtins — встроенные имена Python (len, str, list, tuple, print, set, …).

Схема областей видимости:
- Local (bar): -
- Enclosing (foo): course
- Global: course (не изменяем)
- Builtin: -

Порядок поиска каждого course:
- В функции bar мы пропускаем Local, так как мы использум специальное слово nonlocal. Поэтому берем имя из Enclosing (внешней функции foo)
- В функции foo course есть в Local пространстве.
- Вне функции есть Global имя course
- В builtin нет имени course

### Что сохраняется в замыкании

В функции make_threshold_checker внутренняя функция check использует переменную threshold, которая не является её локальной переменной и не является глобальной. Она берётся из объемлющей области видимости — из вызова make_threshold_checker.

При каждом вызове фабрики создаётся своя ячейка замыкания:

- в замыкании check_4 сохраняется значение 4.
- в замыкании check_5 сохраняется значение 5.

Эти функции независимы: check_4 проверяет result >= 4, а check_5 — result >= 5. Значение порога фиксируется в момент создания соответствующей функции и хранится в её closure-ячейке.

Можно убедиться явно:

```py
print(check_4.__closure__[0].cell_contents)  # 4
print(check_5.__closure__[0].cell_contents)  # 5
```

Итог: apply_to_results принимает любую callable-функцию — именованную или lambda; а make_threshold_checker создаёт независимые функции-проверки, каждая со своим зафиксированным значением threshold в замыкании.


## Задание 5. Анализатор учебных результатов
### Контракты функций
Функция: mean - Возвращает среднее арифметическое.

Контракт:
- values — массив чисел;
- пустой массив -> None;
- исходный массив не изменяется.

Функция: minimum - Возвращает минимум без использования min().

Контракт:
    - пустой массив -> None;
    - исходный массив не изменяется.

Функция: maximum - Возвращает максимум без использования max().

Контракт:
- пустой массив -> None;
- исходный массив не изменяется.

Функция: classify - Возвращает текстовую категорию результата.

Контракт:
- None -> "нет данных";
- score должен быть в диапазоне [0; 100], иначе ValueError;
- границы: 90, 75, 60 относятся к более высокой категории.

Функция: student_summary - Формирует словарь с итогами одного студента.

Контракт:
- results не изменяется;
- для пустого списка mean/min/max равны None, категория — "нет данных".

Функция: find_top_students - Возвращает студентов с наибольшим средним результатом.

Контракт:
- студенты с пустым списком результатов не участвуют в сравнении;
- если нет ни одного результата, возвращается пустой список;
- при равенстве средних возвращаются все лидеры.

Функция: group_summary - Формирует общую статистику группы.

Контракт:
- исходный словарь students не изменяется;
- group_mean считается по всем отдельным результатам;
- студенты с пустыми списками попадают в "нет данных" и не влияют на средний результат группы и поиск лидеров.

Функция: format_report - Формирует итоговый текстовый отчёт.

Контракт:
- student_data — словарь name -> student_summary(...);
- group_data — результат group_summary(...);
- корректно обрабатывает пустую группу и студентов без результатов.

### Сложность формирования отчета группы
Обозначим:

S — число студентов;
N — общее число оценок во всех списках;
k_i — число результатов у i-го студента, N = sum(k_i).

Для одного студента student_summary() вызывает mean(), minimum() и maximum(). Каждая из этих функций делает один проход по его результатам, поэтому student_summary() работает за O(k_i).

В group_summary():

вызов student_summary() для всех студентов — суммарно O(N);
подсчёт общего среднего группы — ещё один проход по всем оценкам, O(N);
подсчёт категорий — O(S);
find_top_students() в текущей реализации повторно вычисляет средние для студентов с непустыми списками — в худшем случае ещё O(N);
построение рейтинга через сортировку — O(S log S).

Итого по времени: O(N + SlogS)

Если у каждого студента есть хотя бы одна оценка, то N >= S, и при большом числе оценок доминирует O(N). Если оценок мало, но студентов много, заметной становится сортировка рейтинга O(S log S).

По памяти: O(S)

### Декомпозиция программы
Декомпозиция заметно повысила читаемость решения. Вместо одной большой функции, в которой смешаны вычисление среднего, поиск минимума и максимума, определение категории, поиск лидеров и форматирование текста, программа разделена на небольшие функции с узкими обязанностями. Благодаря этому основную логику group_summary() можно читать как последовательность понятных шагов: получить сводку по каждому студенту, накопить общий средний результат, посчитать категории, найти лидеров и построить рейтинг. Детали вычислений скрыты в mean(), minimum(), maximum() и classify(), поэтому при чтении не нужно одновременно удерживать в голове все алгоритмы.

Отделение вычислений от вывода также улучшило читаемость: format_report() отвечает только за текст, а не за статистику. Особые случаи — пустая группа, студент без результатов, несколько лидеров — обрабатываются явно и в одном месте, а не размазаны по коду. Небольшие функции проще проверять через assert, поэтому сценарии из задания читаются как документация к поведению программы.

Недостатком можно считать некоторую избыточность: из-за независимости функций средние значения и списки результатов проходятся несколько раз, а find_top_students() повторно вычисляет средние. Однако это не меняет асимптотику O(N + S log S) и окупается ясностью контрактов и удобством сопровождения. В целом декомпозиция сделала решение более предсказуемым, тестируемым и понятным для другого читателя, чем эквивалентный монолитный код.
